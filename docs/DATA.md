# 数据与隐私边界

## 存储

当前 Android 与浏览器版本各自保存数据，互不自动同步。调试包 `app.personal.timeledger` 与正式包 `app.personal.timeledger.official` 分开安装，不能自动共享本地记录。更换包名、签名或存储键会影响升级，必须单独验证数据迁移。

Android 清单已设置 `allowBackup=false`，并为 Android 12 及以上配置了云备份与设备间传输的排除规则。这样与手动导出的产品约定一致；不同厂商的真实迁移行为仍须真机核对。[Android 官方说明](https://developer.android.com/identity/data/autobackup)指出，单靠 `allowBackup=false` 在部分厂商设备上可能无法禁用设备间传输，因此两个规则都需保留。此设置不会清除设备上的现有记录；v25 之前的系统备份状态无法仅凭新 APK 推断。Flomo 直接发送是使用者主动触发的网络行为，应用因此保留网络权限。

完整 JSON 备份用于恢复事件、分类、备注、日志与日／周／月总结。Excel 工作簿包含时间记录、分类、日志和总结，供阅读、筛选与分析；新版导出会在记录表右侧保留旧系统的来源分类、原总时长和原预估时长，重新导入时保留这些字段。旧版可读 Excel 没有这些列；在同一设备导入时会尝试保留现有记录的来源字段，并拒绝会删去已有记录的旧表。JSON 仍是首选完整备份，因为 Excel 不承载所有内部字段。CSV 仅供阅读。Flomo 接入地址只保存在当前设备设置里，不进入完整 JSON 备份或 Excel；调试版原始数据提取物可能包含该地址。

将手机的完整 JSON 备份复制到电脑上的私有目录（不在任何 Git 仓库内）后，可先运行 `node scripts/check-private-backup.mjs "<私有备份文件路径>"`。工具只读文件，调用与应用相同的导入校验，并再次序列化、解析；终端仅输出字节数、SHA-256 及事件、分类、日志、总结条数，不输出备注。它是恢复前检查，不能替代在隔离资料中实际导入、逐项抽查，也不能证明手机上的原始数据与该文件完全一致。

若还持有旧「时间日志」导出的 `.xls`，可在私有电脑上运行 `node scripts/compare-legacy-backup.mjs "<旧导出.xls>" "<完整备份.json>"`。它只读解析两份文件，按来源行号核对原事件的时间、分类名、备注、时长、预估与标签，以及日志的日期、类型和正文；输出只有汇总数字。`complete: true` 仅表示**所选旧快照**的内容都在所选备份中，不能证明旧 App 后续没有新增记录，也不能证明手机此刻没有更新。迁移时仍需最新旧导出和最新手机备份。

若同时有本产品导出的可读 `.xlsx`，可运行 `node scripts/compare-migration-snapshots.mjs "<旧导出.xls>" "<可读表格.xlsx>" "<完整备份.json>"`。它只输出文件哈希、数量及重叠、缺失、变化字段的计数，不输出私人备注；可按旧来源行号核对两张表共同保留的起止时间、分类 ID 和备注，也可按事件 ID 比较 JSON 与可读表。可读表不包含全部内部来源字段，因此这一步不能替代同期完整 JSON 的恢复演练。比较结果必须结合三个文件各自的导出时间解释。

如果旧版可读表格已经被导入，造成新备份缺少旧系统来源字段，但仍保留较早的完整 JSON，可在**仓库外的私有目录**运行 `node scripts/recover-legacy-provenance.mjs "<较早完整备份.json>" "<较新完整备份.json>" "<新的私有修复候选.json>"`。工具要求较早事件在新备份中仍存在，并逐条核对旧来源事件的 ID、起止时间、分类、备注和来源行号；仅把缺失的旧来源字段补入新文件，不覆盖任一原件。输出路径已存在或内容冲突时直接拒绝。生成候选后仍须用 `check-private-backup.mjs`、`compare-legacy-backup.mjs` 和隔离恢复核对，才考虑迁移手机。

若启动时本机记录无法解析，应用会停止编辑和保存，避免用空账本覆盖原始内容。若还能读取到原始文本，可从恢复页导出 `.txt` 副本供私下排查；它不等于可直接恢复的完整 JSON 备份。不要把该副本上传到公开仓库。

## 公开仓库允许与禁止

允许：独立编写的源代码、构建脚本、虚构样本、匿名的行为测试、公开产品说明、第三方依赖许可。

禁止：个人时间明细或总结、任何旧 XLS/XLSX/CSV/JSON 备份、原应用 APK 与逆向产物、用户录屏和聊天截图、私人 Wiki 内容、Flomo webhook、Android 签名密钥、SDK 本机路径、包含个人数据的截图和安装产物。

发布前检查 Git 历史、提交作者与提交者邮箱以及当前树；删除工作区文件不足以清除历史。`node scripts/verify-source.mjs` 会报告历史中非 GitHub 隐私邮箱的数量，但不会打印地址；它仅作提醒，不阻止贡献者使用自己的公开邮箱。首次公开或改写历史前仍要人工检查元数据。任何示例截图均须由虚构数据重新生成并人工核对。第三方库的许可证必须随代码保留。

## 备份与更新

覆盖安装既有 APK 前，先取得非零完整备份并完成隔离恢复核对；仅检查文件存在不够。若导出失败，暂停升级，按[调试版数据应急预案](ANDROID_DATA_RESCUE.md)评估只读提取。安装后核对记录条数及最近条目；不要卸载旧版或清除应用数据。建议定期导出完整备份并核对文件与行数。恢复演练应在隔离环境中做，不用真实主账本试错。
