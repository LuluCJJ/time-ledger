The disposable key and APK are not release artifacts; the real key and phone transition remain pending. See [Android release process](ANDROID_RELEASE.md).

An earlier local trial build was v37 at `shells/dist/TimeLedger-preview-2026-10-24-v37.apk` (Git-ignored), SHA-256 `7DAB6C99F2271EC1A07ACF72C4838FDB1D7063EE851F64A18D54A45C7C06B924`. It keeps the v36 native export and license changes but makes the page report success only when native read-back verification is explicitly true and the byte count is positive; a legacy or incomplete native response now warns that the file cannot be treated as a backup. The APK contains web version 43 and that stricter message, and its debug signer digest matches v36. A user's phone screenshot on 2026-10-24 showed two earlier full-backup JSON files at 0 B; the user subsequently reported that the current app crashes during export. The exact crash stack is still unknown; v37 was installed when the user reproduced the crash. The v35–v37 export flow stages bytes in app-private storage before opening Android's file picker, writes the chosen document, and requires a matching byte count and SHA-256 read-back before reporting success; it retries through a second write path if the first read-back differs. A failed export can leave a zero-byte file in the chosen folder, so users must retain the app data and inspect the result. Compilation and signature verification passed; the phone behavior is **not yet verified**, and the user later installed v37 but reported that export still crashed. A [read-only debug-data rescue procedure](ANDROID_DATA_RESCUE.md) is prepared for an authorized USB connection; it has fixture tests, but has not run on the user's device. v37 also carries the v32 storage write rollback and v34 narrowed camera FileProvider scope. Actual phone interaction, export read-back and data preservation still require a phone check. No APK is included in this source repository.

## Android export follow-up

After the user reported v37 still crashes while exporting, v38 switches Android 10+ exports to direct insertion in `Download/TimeLedger` through MediaStore, without launching the document picker. The app publishes a file only after a byte count and SHA-256 read-back match; failures attempt to delete the incomplete entry. Android 9 and older retain the picker path. The local trial APK is `TimeLedger-preview-2026-10-24-v38.apk`, SHA-256 `3DC72A108E9D7CE3A6CDEC320BC20FE8EFAA622FE51BA19261B64A05D97FAB4C` (4,840,627 bytes); it has the same package ID, versionCode and debug signer as v37. Compilation and APK signature verification passed, but the direct export route has **not** been tested on the user's phone; the root cause of the earlier crash remains unknown. No old zero-byte file should be treated as a backup.
